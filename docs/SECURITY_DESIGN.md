# SECURITY_DESIGN — 执行安全与沙箱设计

> Phase 0 设计文档 · 状态:待确认
> 上游需求:README 第六节「执行安全」:用户代码属于不可信输入;不能把超时当成完整沙箱;做不到隔离的模式必须明确标记并默认禁用。

## 1. 威胁模型

**部署形态:** 本地个人学习工具,后端只监听 127.0.0.1,单用户。

**保护对象:** 宿主机文件系统、网络、其他进程;平台自身数据(data/、数据库)。

**攻击面:** 用户在编辑器里写的汇编/C++ 代码(视为不可信输入,即使作者就是本人——防误操作与防实验性破坏代码,如死循环、内存炸弹、真实 syscall)。

**明确的非目标(如实声明,不做虚假承诺):** 本工具不是防恶意用户的多租户云沙箱。模式 B 的进程级隔离针对「误操作与资源失控」,不承诺对抗蓄意提权攻击。这一限制会写进 UI 与文档。

风险分级:

| 级别 | 场景 | 措施 |
|---|---|---|
| L1 | 死循环/超长循环 | 指令数上限 + 墙钟超时,双保险 |
| L2 | 野指针写飞内存 | 模式 A:封闭内存映射,越界访问直接报错并停在出错指令;模式 B:进程内自身崩溃,不影响宿主 |
| L3 | 真实系统调用(读写文件、网络) | 模式 A:syscall 桩(只有 write/exit 等教学实现);模式 B:Job Object 限制 + 平台策略(见 §4) |
| L4 | 无限申请内存 | 模式 A:内存映射固定;模式 B:Job 内存上限 |

## 2. 模式 A(指令模拟器)——结构性隔离

Unicorn 模拟器的隔离来自构造,而非限制:

1. **内存是封闭的:** 只有 `mem_map` 映射过的教学沙箱四段(代码/数据/栈/堆,共几 MB)可访问。映射之外的任何读写取指都触发 fault,hook 捕获后转为友好错误(「访问了未映射地址 0x…」),不触碰宿主内存。
2. **系统调用是桩:** `syscall` 指令由 INSN hook 拦截,平台只实现教学子集(Linux `write=1`、`exit=60`、`read=0`、`brk=12`),其余一律返回错误并暂停。不存在通往真实内核的路径。
3. **无外部副作用:** 模拟器内不可能打开文件、发起网络、fork 进程——这些语义根本没有实现。
4. **资源上限(RunControl,引擎强制):**

| 限制项 | 默认值 | 说明 |
|---|---|---|
| 单次 run 最大指令数 | 1,000,000 | 防死循环;UI 可见「已到上限」并停在当前步 |
| 会话总指令数 | 10,000,000 | 防多次 run 累计拖垮后端 |
| 墙钟超时(单次 run) | 5 s | code hook 里检查,超时 uc_emu_stop |
| 内存映射总量 | 8 MB | isa.toml 中固定,装载时分配 |
| 栈大小 | 1 MB | 超出即未映射 fault |

5. **崩溃边界:** 模拟器运行在专用 actor 线程;若引擎异常,只终止该会话,后端存活,前端得到明确错误。DLL 加载失败时模式 A 整体不可用并给出安装指引(功能降级而非崩溃)。

**模式 A 结论:可以安全执行不可信代码,是 Phase 1 唯一启用的执行模式。**

## 3. 模式 B(真实程序调试,Phase 2+)——进程级限制

隔离手段按平台:

### Windows(主环境)

- **Job Object**(win32job crate):编译产物与 gdb 等子进程全部挂入 job;`JOB_OBJECT_LIMIT_PROCESS_MEMORY`(默认 512 MB)、CPU Rate Control(可选)、`KILL_ON_JOB_CLOSE`(超时杀整棵进程树,不留孤儿)。
- **超时:** 每个外部进程调用(nasm/clang/gdb)带 wall-clock 超时 + 输出截断(防巨量输出内存膨胀)。
- **文件系统:** 每次会话在 `%TEMP%/assemblylab/<uuid>/` 建唯一目录,源码、产物、调试输出全在其中;会话结束/进程退出时删除;后端启动时清扫孤儿目录。被调试程序只获得该目录作为 CWD。
- **环境变量:** 子进程环境白名单(最小 PATH、TEMP),不透传宿主全部变量。
- **网络:** 无内置网络需求;被调试程序若自行联网,受 Windows 默认防火墙提示,平台不主动放行。此点在 UI 上如实标注为「未隔离」项。

### WSL2 / Linux(可选路径,Phase 2)

- 同样的临时目录与超时策略;进程限制用 `prlimit`(RLIMIT_AS/RLIMIT_CPU/RLIMIT_FSIZE/RLIMIT_NPROC);如需强化,Phase 6 评估 seccomp(用户态白名单)或 bubblewrap。默认配置下明确标注隔离等级为「进程级限制」。

### 不可能时的降级(README 硬性要求)

设置页的「执行模式」开关:

| 模式 | Phase 1 | Phase 2+ |
|---|---|---|
| A 模拟器 | ✅ 默认启用 | ✅ |
| B Windows 原生调试 | ❌ 不存在 | ✅ 启用,标注「进程级隔离,非强沙箱」 |
| B WSL 调试 | ❌ | ⚙️ 检测到 WSL+工具链才出现,同样标注 |

未达标(如缺工具)时按钮禁用并显示原因,而不是允许执行后再失败。

## 4. 外部工具进程安全(汇编/编译/调试器)

- **源码经临时文件传入,绝不拼接进命令行**(防参数注入);文件名由平台生成,用户输入不参与路径构造。
- 所有工具调用统一走 `ToolAdapter` 的超时包装(默认 30 s 编译 / 5 s gdb 命令),输出上限 1 MB,超限截断。
- gdb/被调试进程同挂 Job Object;gdb 以 `-batch` 或 MI 模式受控驱动,禁用其 shell 命令(gdb 内 `!`/`shell`)——通过 MI 白名单命令集实现,不透传用户原始命令。
- 下载的预编译库(unicorn.dll)只从官方 GitHub release 获取,校验来源 URL,存放于 `spikes/`(验证用)或产品分发时的固定位置;不执行任何下载内容的代码以外的隐式行为。

## 5. 数据与配置安全

- AI 助教的 api_key 只存本地 SQLite(settings 表),永不写入仓库与日志;AI 请求只发送与当前教学相关的结构化上下文(StepReport、ISA 注释、用户答案),不发送课程库全文或文件系统内容。
- 日志(tracing)不记录用户源码全文,只记录会话元信息与错误摘要(可配置)。
- 后端默认绑定 `127.0.0.1`;如需局域网访问必须用户显式改配置并弹出警示(README 定位是本地工具)。

## 6. 供应链与依赖

- cargo/npm 锁文件入库;新增依赖(尤其带 build.rs 的)需在 PR 级记录理由。
- `spikes/` 下的一切(含下载的 .7z/解压产物)明确标记非产品代码,不进入构建图;产品化时 unicorn.dll 的获取、校验与打包方式在 Phase 1 开工前单独确认(见 ROADMAP Phase 1 任务 1)。

## 7. 决策记录

| # | 决策 | 备选 | 理由 |
|---|---|---|---|
| D-SEC-1 | 模式 A 以「结构性隔离」为安全边界,不叠加系统沙箱 | 给模拟器再套 AppContainer/容器 | 模拟器无宿主访问路径,系统沙箱徒增复杂;把力气花在模式 B |
| D-SEC-2 | 模式 B 用 Job Object + 超时 + 临时目录,如实标注「进程级限制」 | Docker 容器、AppContainer、虚拟机 | 本地工具的最小可靠方案;Docker 可作为未来可选项,不设为默认依赖 |
| D-SEC-3 | syscall 一律桩实现,不做真实系统调用穿透 | 转发真实 Linux syscall | 穿透即失去模式 A 的隔离价值;教学只需 write/exit 少数几个 |
| D-SEC-4 | 不可用模式显式禁用 + 原因展示,而非静默失败 | 全部开放,失败再说 | README 硬性要求 |
