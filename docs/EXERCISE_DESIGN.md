# EXERCISE_DESIGN — 习题与判题系统

> Phase 0 设计文档 · 状态:待确认
> 上游需求:README 第八节。核心立场:习题不止选择题;判题确定性优先;不把 AI 评价当标准答案。

## 1. 判题能力分级

| 级别 | 机制 | 适用题型 | 可信度标注 |
|---|---|---|---|
| **L-A 确定性判题** | 用户代码/答案进隔离会话真实执行,断言寄存器/标志/内存/输出 | 预测结果、补全汇编、综合编程、Bug 修复、调试挑战 | 「引擎判题,结果可信」 |
| **L-B 结构化比对** | 答案按结构(寄存器值列表/代码 diff/C++ 片段规范化)比对参考 | 预测结果的值填写、C++ 转汇编分析要点 | 「自动比对 + 自核」 |
| **L-C 自评/AI 辅助** | 参考解析自评;可选 AI 基于真实上下文给参考意见 | 原理解释、汇编转 C++ 的开放部分 | 「非权威,仅供参考」 |

任何一题的「通过」状态只由 L-A/L-B 决定;L-C 只影响反馈丰富度。AI 未配置时 L-C 降级为展示参考解析。

## 2. 八种题型的判题设计(README 第八节逐项)

| # | 题型 | 判题机制 |
|---|---|---|
| 1 | **预测执行结果** | 答案为结构化断言(RAX/RBX/RFLAGS/内存终值);提交后引擎执行同一段汇编,逐项比对(L-A + L-B)。答案在提交前不可见,比对明细展示每项 ✓/✗ 与真实值 |
| 2 | **补全汇编** | 用户补全片段 → 完整程序进会话,跑 `testcases`(多组输入输出断言)(L-A)。语法错误先行返回汇编器错误定位 |
| 3 | **汇编转 C++** | 关键行为断言(用户 C++ 片段可选填)+ 参考答案自评清单(L-C 为主,辅以代码语义关键词比对 L-B);AI 可给对比意见 |
| 4 | **C++ 转汇编分析** | 多点选择/填空(哪条指令对应哪行 C++、参数在哪个寄存器)取自真实编译产物,逐点比对(L-B);附逐步解析 |
| 5 | **Bug 修复** | 用户改代码后执行 `testcases`;通过 = 修复。记录修改 diff 用于解析展示 |
| 6 | **调试挑战** | 提供可运行但藏着问题的程序 + 目标(找到栈破坏点等);判定方式 = 回答定位(地址/指令/变量名,结构化)+ 可选修复验证(L-A/L-B) |
| 7 | **综合编程** | 同 #2,题规模大(数组求和/strlen/排序/简单上下文切换原型/自旋锁);多组 testcases + 资源上限(指令数/内存),防「碰运气暴力枚举」 |
| 8 | **原理解释** | 自评标准清单(要点逐条勾选)+ 参考解析;可选 AI 对照「知识点要点集」给参考意见(L-C) |

## 3. 判题执行模型

- 用户代码判题一律走**模式 A 会话**(L-A),RunControl 用更严的上限(如 100k 指令、1MB 内存),互不影响工作台会话。
- `testcases` 结构:每组 = {输入(预置内存/寄存器初值), 断言(终值/输出序列/访存序列)};判题器循环装载→执行→断言,汇总报告。
- 失败输出分层:语法错误(汇编器行号)/ 运行错误(未映射访问地址)/ 断言失败(期望 vs 实际,含每步 diff 入口直达工作台回放)。
- 防碰运气:综合编程题断言组数 ≥3 且含边界输入;预测题提交后锁定一次作答,重做需重置记录(本地工具,防误触不防意志)。

## 4. 习题数据 schema(data/exercises/**)

```toml
[exercise]
id = "stage02-q03"
type = "predict"            # predict | fill-blank | asm2cpp | cpp2asm | fix-bug | debug-challenge | programming | explain
title = "SUB 之后标志位会怎样?"
stage = 2
lesson = "stage02-lesson03"
knowledge = ["flags-cf", "flags-of", "sub"]     # 知识图谱节点
difficulty = 2              # 1–5
est_minutes = 8

[exercise.presentation]
asm = '''
mov rax, 0x7FFFFFFFFFFFFFFF
mov rbx, 1
add rax, rbx
'''
questions = [               # 结构化作答项
  { key = "RAX", prompt = "RAX 最终值(hex)", expect = "reg:RAX" },
  { key = "OF",  prompt = "OF?", expect = "flag:OF" },
]

[exercise.judge]
model = "run-and-compare"   # run-and-compare | testcase | self-check | ai-assisted
testcases = "cases.toml"    # L-A 用例文件
reference = "answer.md"     # 参考答案与完整解析(提交前不渲染)

[exercise.hints]            # 提示梯度(README 要求)
level1 = "注意这条加法的两个操作数在有符号视角下的和。"
level2 = "0x7FFF…F 是 INT64_MAX;加 1 会发生什么?想想 OF 的判定规则(两正得负)。"
reveal = true               # 允许主动看答案 → 展示 answer.md 全文

[exercise.related]
experiments = ["stage02-calc"]
lessons = ["stage02-lesson03"]
```

反馈机制字段(题目目标/难度/知识点/输入/预期/判题条件/参考答案/解析/常见错误/关联实验)全部进 schema 或 answer.md 结构,UI 渲染固定布局。

## 5. 提示与防挫败(README 反馈机制)

- 错误第 1 次 → `hints.level1`(方向性);第 2 次 → `hints.level2`(具体);用户主动「查看答案」→ 解析全文 + 标记该题为「已看答案」(不计入通过,进度以一次独立通过为准)。
- 判题报告含「常见错误」段落(`answer.md` 固定小节),命中典型错误模式时(如把 OF/CF 混淆)优先展示对应条目。
- 错题自动进入「错题本」(SQLite exercise_attempt 状态机:未做/尝试中/通过/已看答案/错题),可重做与收藏(README 习题中心要求)。

## 6. 决策记录

| # | 决策 | 备选 | 理由 |
|---|---|---|---|
| D-EX-1 | 判题三级分型,通过状态只认 L-A/L-B | 全部 AI 判 | 确定性可复核;README 明确「不能把没有可靠依据的自动评价当标准答案」 |
| D-EX-2 | 习题执行与工作台会话隔离(独立更严 RunControl) | 复用工作台会话 | 判题可重入、可并行、防误改用户工作状态 |
| D-EX-3 | 参考答案文件化并延迟渲染 | 内嵌题目 JSON | 防 UI 端意外泄露;便于 review 与测试(每题 answer 必须经过判题自洽校验) |
| D-EX-4 | 每题必带 judge 用例 | 允许无用例解释题 | L-C 题型也要有「要点集」供自评;保证 README 第十一节第 7 条(参考答案经过测试) |
